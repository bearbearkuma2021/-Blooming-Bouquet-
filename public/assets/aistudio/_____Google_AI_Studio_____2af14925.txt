## 企劃摘要

《靜綻花語 Blooming Bouquet》是一款以「慢慢種下一朵花，再親手把心意包裝起來」為核心概念的療癒系 2D 互動網頁。使用者可在具有日夜變化與隨機彩蛋的花田中，繪製或挑選花卉，完成栽種與採收；接著將花朵自由編排成束，搭配多層包裝紙、緞帶與吊牌，最後製作專屬賀卡並匯出圖片。

本企劃採分階段精靈式流程，降低初次使用者的操作負擔，同時保留足夠的自由創作空間。開發上以可先完成核心流程、再逐步擴充特效與素材的方式安排，確保專案能在有限時程內完成可展示、可操作的 MVP（最小可行產品）。

## 一、專案概述


### 1.1 專案背景

數位賀卡與線上創作工具多以快速套版或單一圖片編輯為主，較少將「花卉培育」與「花束製作」整合成具有過程感的互動體驗。本專案希望將種植、採收、編排、包裝與傳遞心意串成一段完整旅程，讓使用者不只是選擇一張現成圖片，而是能透過自己的操作完成一份具有個人風格的作品。


### 1.2 專案目標

建立具有四大時段循環、天氣效果與隨機彩蛋的 2D 花田場景。

提供簡易 DIY 繪圖工具，讓使用者能創作專屬花朵素材。

提供預設花卉、栽種呈現與採收籃，建立由花田進入花束製作的流程。

提供可自由編排的花束畫布，以及三層包裝紙、圖樣上傳與裝飾配件。

提供賀卡文字與塗鴉功能，並能將完成作品匯出為圖片。

以清楚的操作提示與響應式介面，支援桌面及行動裝置使用。

### 2.1 目標受眾


### 2.2 典型使用情境

情境一｜日常療癒：使用者開啟花田，切換時段、觀察天氣與彩蛋，再採收喜歡的花朵。

## 三、產品流程與功能規格


### 3.1 整體使用流程

使用者依序完成三個主要階段；系統應顯示目前進度，並允許在不遺失已完成內容的前提下返回前一階段修改。


### 3.2 Phase 1：動態花田與栽種系統


#### A. 花田視覺與前後景佈局

畫面以天空、遠景、花田地面與植物層次構成；主要互動區域集中於畫面下半部。

前景花卉為可點擊與採收的主要對象，使用正常彩度與明度呈現。

後景花卉以降低彩度、明度或加入輕微模糊的方式處理，營造景深。

前後景應在視覺上清楚區隔，並確保前景可互動物件不會被背景裝飾遮擋。

花田素材需保留可擴充性，未來可增加季節植物、裝飾物與不同地景。


#### B. 四大時段與手動刷新

時段固定依序循環：白天（DAY）→ 下午／黃昏（SUNSET）→ 晚上（NIGHT）→ 清晨（DAWN）→ 白天。使用者點擊「手動刷新時段」後，系統推進一個時段；刷新成功後開始 10 分鐘冷卻，冷卻期間按鈕停用並顯示倒數。

事件觸發採機率判定。每次刷新只判定新進入的時段，不沿用上一時段事件；若沒有觸發事件，則顯示一般天氣／場景。建議初期將事件總觸發率設定為 30% 作為可調整參數，實際數值可於測試後平衡。

機率設定建議：先抽取「是否出現事件」；若成功，再依該時段可用事件池抽選。如此可避免白天抽到流星、晚上抽到彩虹等不符合規則的結果。雨天若設定為跨時段事件，需決定是否與彩虹等事件互斥；本企劃 MVP 建議同一刷新最多出現一種主要事件，以簡化視覺與狀態管理。


#### C. DIY 花朵繪圖畫板

基本工具：畫筆、橡皮擦、復原、重做、清除畫布。

畫筆設定：顏色、粗細、透明度；提供常用色票與自訂色彩選擇。

輔助區域：花頭區域、花莖／葉片區域提示線，可切換顯示與隱藏。

輸出格式：透明背景 PNG，並保留花朵素材供後續花田或花束流程使用。

操作需求：支援滑鼠與觸控；若裝置不支援壓力感應，筆畫仍須正常運作。


#### D. 預設花卉庫與採收

內建 8–12 種常規花卉，統一採 2D 扁平或柔和水彩風格。

花卉至少具備名稱、縮圖、素材圖、花色與可採收狀態等資料。

點擊成熟的前景花朵即可加入採收籃；已採收花朵需呈現狀態變化，避免重複採收。

採收籃至少 3 朵才可進入 Phase 2，上限 12 朵；超過上限時顯示提示。

若使用者尚未採滿 3 朵，應提示目前數量與尚需採收數量。


### 3.3 Phase 2：花束組裝與包裝系統


#### A. 花朵自由編排

將採收籃中的花朵拖曳至花束工作區，可自由移動位置。

提供縮放、旋轉、刪除／移除與複製等基本操作。

提供圖層前移、後移、置頂、置底功能，調整花朵遮擋關係。

支援工作區縮放或適應畫布，避免手機螢幕操作困難。

離開此階段前保留構圖狀態，返回修改時不應重置。


#### B. 三層包裝紙結構


#### C. 自訂包裝紙圖樣上傳

支援 JPG／PNG 圖片上傳，建議使用正方形圖片以獲得較均勻的平鋪效果。

使用 Pattern 或 SVG 遮罩將圖樣套用於指定包裝紙圖層。

提供預覽與重新上傳功能；檔案格式不符或載入失敗時顯示清楚提示。

應限制檔案大小並檢查圖片載入結果，避免大型圖片影響效能。


#### D. 配件與飾品

提供絲帶、蝴蝶結、麻繩、蕾絲與裝飾吊牌等素材。配件可移動、縮放與旋轉；吊牌可連結 Phase 3 的卡片文字或使用者自行輸入短句。


### 3.4 Phase 3：賀卡撰寫與導出


#### A. 心意小卡

支援新增、編輯與刪除文字，調整字型、字級、顏色、對齊與行距。

支援手繪塗鴉，提供畫筆、橡皮擦、復原與清除功能。

卡片可調整尺寸、位置、旋轉角度與層級，並能預覽最終成品。

提供數種預設卡片樣式，讓使用者可快速開始，也可選擇空白卡片自由編輯。


#### B. 導出與分享

支援 1:1 與 4:5 兩種常用輸出比例。

優先提供 PNG；如採 JPG，需將透明區域合成指定背景色。

匯出解析度應高於或等於預覽畫布，並避免介面按鈕、選取框等編輯輔助元素被輸出。

桌面端提供下載圖片；行動端提供下載或 Web Share API 分享能力（依瀏覽器支援狀況）。

分享 API 不可用時，應提供一般下載作為替代方式。


## 四、介面與視覺設計規範


### 4.1 視覺定位

整體採溫柔、安靜、帶有手作紙感的療癒風格。畫面應避免過度鮮豔或高密度裝飾，讓花朵與使用者作品成為視覺焦點。

## 六、核心互動邏輯


### 6.1 時段推進與冷卻規則

初始時段可設定為白天，或依產品啟動時間選擇預設時段；MVP 建議固定白天以利展示。

使用者按下刷新且冷卻已結束時，時段索引加一並以循環方式回到起點。

刷新成功後記錄下一次可刷新時間（時間戳），並啟動 10 分鐘倒數。

冷卻期間按鈕 disabled，倒數歸零後重新啟用。

重新整理頁面或關閉瀏覽器後，應以保存的時間戳計算剩餘冷卻，不可單純依賴頁面計時器。

若使用者系統時間被調整，應以剩餘時間不小於 0 的方式處理，避免出現負數倒數。


### 6.2 彩蛋判定建議

建議將「事件總機率」與「事件種類」分開處理，並以設定表管理機率，避免把機率寫死在多個程式區塊。以下程式為概念示例，機率數值可依測試調整。

const TIME_SEQUENCE = ['DAY', 'SUNSET', 'NIGHT', 'DAWN'];

const EVENT_POOL = {
  DAY: ['RAIN', 'RAINBOW'],
  SUNSET: ['RAIN', 'FOX'],
  NIGHT: ['RAIN', 'METEOR'],
  DAWN: ['RAIN']
};

function rollEvent(newPeriod, eventRate = 0.3) {
  // 先判斷是否觸發任何事件
  if (Math.random() >= eventRate) return null;

  // 再從當前時段允許的事件中抽選
  const pool = EVENT_POOL[newPeriod] ?? [];
  if (pool.length === 0) return null;

  return pool[Math.floor(Math.random() * pool.length)];
}

function handleManualRefresh(currentIndex, canRefresh) {
  if (!canRefresh) return null;

  const nextIndex = (currentIndex + 1) % TIME_SEQUENCE.length;
  const newPeriod = TIME_SEQUENCE[nextIndex];

  return {
    newIndex: nextIndex,
    newPeriod,
    triggeredEvent: rollEvent(newPeriod),
    nextRefreshAt: Date.now() + 10 * 60 * 1000
  };
}


### 6.3 採收規則

採收前檢查花朵是否位於可採收前景、是否已採收，以及採收籃是否已達上限。若採收籃數量為 12，系統不得再加入新花朵；若數量少於 3，Phase 2 的前進按鈕維持停用。


### 6.4 花束編排與匯出

每朵花與每個裝飾物均應視為獨立畫布物件，至少保存素材識別碼、位置、縮放、旋轉角度與圖層順序。匯出時使用專用輸出畫布或暫時隱藏編輯器控制項，避免選取框、工具列或輔助線被合成到成品。

## 結語

《靜綻花語 Blooming Bouquet》希望讓使用者在一段不急不徐的互動流程中，完成一份真正屬於自己的花束作品。專案的核心不只是視覺裝飾，而是透過時段變化、偶發彩蛋與自由編排，讓每次進入花田都保有一點期待，也讓最後匯出的賀卡承載個人創作與情感。

本文件可作為專案提案與初期開發依據；正式進入製作前，仍建議確認開發人力、採用框架、素材規格、彩蛋機率及各階段優先順序。

| 手作與療癒系玩家 | 喜歡塗鴉、花藝、微縮模型與慢節奏互動 | 自由繪花、照料花田、嘗試不同花束組合 |

| 節慶與心意傳遞者 | 需要生日、母親節、情人節、畢業季等祝福素材 | 製作專屬花束與賀卡，匯出後傳送給對方 |

| 社群分享者 | 喜歡分享有個人特色的視覺作品 | 設計具有美感的花束圖卡並保存分享 |





| 階段 | 主要任務 | 完成條件 |

| --- | --- | --- |

| Phase 1｜花田與採收 | 瀏覽花田、切換時段、繪製／選擇花卉、採收 | 採收籃至少有 3 朵花，最多 12 朵 |

| Phase 2｜花束組裝 | 編排花朵、調整層級、選擇包裝與配件 | 完成可預覽的花束構圖 |

| Phase 3｜賀卡與導出 | 編輯文字、塗鴉、調整卡片位置、匯出 | 成功產生 PNG 或 JPG 成品 |





| 時段 | 英文代碼 | 場景方向 | 可觸發事件 |

| --- | --- | --- | --- |

| 白天 | DAY | 明亮、清爽、自然光 | 雨天、彩虹 |

| 下午／黃昏 | SUNSET | 暖橘、柔和夕光 | 雨天、好運狐狸 |

| 晚上 | NIGHT | 深藍夜色、星空 | 雨天、流星雨 |

| 清晨 | DAWN | 淡紫、粉橘、晨霧感 | 雨天（其他彩蛋保留擴充） |





| 事件 | 觸發時段 | 呈現方式／限制 |

| --- | --- | --- |

| 雨天（RAIN） | 四時段皆可能 | 雨滴粒子、地面濕潤或雨聲；可與當前時段色調共存 |

| 彩虹（RAINBOW） | 僅白天 | 天空出現彩虹，避免遮擋花田操作區 |

| 流星雨（METEOR） | 僅晚上 | 夜空出現流星動畫，可採短時間循環 |

| 好運狐狸（FOX） | 僅下午／黃昏 | 狐狸出現在花田背景，作為稀有視覺彩蛋 |





| 層級 | 位置與功能 | 設計要求 |

| --- | --- | --- |

| 內層（Inner） | 花束後方的襯底 | 提供柔和底色或紙材質感，作為花束背景 |

| 中層（Middle） | 包覆花束主體輪廓 | 形成主要包裝形狀，可呈現摺線或紙張弧度 |

| 外層（Outer） | 位於前方與兩側 | 呈現立體摺角與包覆感，與花朵產生前後遮擋 |

| 狀態類別 | 欄位範例 | 用途 |

| --- | --- | --- |

| 時段 | currentPeriod、currentEvent、nextRefreshAt | 記錄目前時段、事件與冷卻截止時間 |

| 花卉素材 | flowerId、name、image、color、growthState | 管理預設或自創花朵 |

| 採收籃 | harvestedFlowerIds | 保存已採收花朵清單 |

| 花束 | objects[]：id、type、x、y、scale、rotation、zIndex | 保存花朵、包裝與配件的畫布狀態 |

| 賀卡 | text、font、fontSize、color、position、doodleData | 保存卡片文字與塗鴉 |

| 匯出 | aspectRatio、format、resolution | 保存匯出比例、格式與解析度設定 |





| 階段 | 預計時長 | 工作內容 | 主要產出／檢核點 |

| --- | --- | --- | --- |

| Phase 1 | 1 週 | 需求確認、頁面流程、時段循環、冷卻與事件判定 | 時段可正確循環；冷卻可跨重新整理保存 |

| Phase 2 | 1 週 | UI 視覺、花田前後景、時段背景與彩蛋素材 | 完成主要畫面與事件視覺展示 |

| Phase 3 | 1.5 週 | DIY 繪圖、預設花卉、採收、花束拖曳與包裝 | 完成採收至花束組裝的核心流程 |

| Phase 4 | 1 週 | 賀卡編輯、塗鴉、圖片合成與匯出 | 可輸出 1:1／4:5 成品圖片 |

| Phase 5 | 0.5 週 | 手機適配、跨瀏覽器測試、效能修正 | 完成基本驗收與展示版本 |





| 測試項目 | 測試方式 | 通過標準 |

| --- | --- | --- |

| 時段循環 | 連續刷新四次 | 依序 DAY→SUNSET→NIGHT→DAWN→DAY，無跳號 |

| 冷卻限制 | 刷新後立即再次點擊 | 按鈕停用並顯示倒數；10 分鐘後恢復 |

| 冷卻保存 | 刷新後重新整理頁面 | 仍能正確計算剩餘冷卻時間 |

| 事件限制 | 多次切換時段觀察事件 | 彩虹只在 DAY、流星只在 NIGHT、狐狸只在 SUNSET 出現 |

| 採收數量 | 採收 0、2、3、12、13 次 | 少於 3 不可進下一階段；最多 12 朵 |

| 花束編排 | 拖曳、縮放、旋轉與調整圖層 | 物件位置與層級正確更新 |

| 圖樣上傳 | 上傳 JPG、PNG 與不支援格式 | 支援格式可套用；錯誤格式有提示 |

| 圖片匯出 | 輸出 1:1 與 4:5 PNG/JPG | 比例正確、畫面完整、無編輯控制項殘留 |

| 行動端操作 | 以手機觸控操作主要功能 | 可完成主要流程，按鈕與畫布操作正常 |





| 風險 | 可能影響 | 因應方式 |

| --- | --- | --- |

| 功能範圍過大 | 時程延誤、核心流程未完成 | 先定義 MVP，進階特效與素材放入後續版本 |

| 畫布引擎學習成本 | 拖曳、圖層或匯出實作時間增加 | 先製作技術原型，確認套件能力後再進入完整開發 |

| 自訂圖片檔案過大 | 載入緩慢或記憶體占用過高 | 限制檔案大小、縮圖預覽並處理錯誤狀態 |

| 冷卻計時不可靠 | 重新整理後冷卻重置或倒數錯誤 | 保存截止時間戳，重新載入時重新計算 |

| 手機畫布操作不便 | 使用者難以精準拖曳與編排 | 設計觸控尺寸、縮放控制與適合手機的工具列 |

| 名詞 | 說明 |

| --- | --- |

| MVP | Minimum Viable Product，最小可行產品；先完成能驗證核心價值的必要功能。 |

| Canvas | 網頁繪圖畫布，可用於繪製、合成與輸出圖像。 |

| Pattern | 將圖片作為重複圖樣填入指定形狀或區域。 |

| SVG Mask | 以向量圖形遮罩限制圖樣顯示範圍。 |

| Z-Index | 物件前後堆疊順序，數值或索引越高通常越靠前。 |

| Web Share API | 瀏覽器提供的原生分享能力，支援狀況依裝置與瀏覽器而異。 |

| LocalStorage／IndexedDB | 瀏覽器本機儲存機制，分別適合少量設定與較大量資料。 |
